# @verdeect/identity-nav-vue

Компоненты кросс-сервисной навигации Verdeect Identity и вывод состояния рейла
для продуктов установки на Vue 3.

**Эталон живёт здесь.** Компоненты рейла и блока пользователя не пишутся заново
и не копируются в продукты: копия породила бы вторую версию, расходящуюся
с эталоном на первом изменении. Правка идёт в этот пакет, продукты получают её
обновлением зависимости.

## Входы

| Вход | Содержимое | Зависимости |
| --- | --- | --- |
| `.` | `CrossServiceRail`, `CrossServiceMenu`, `CrossServiceBar`, `UserMenu` и их типы | `vue` |
| `./style.css` | визуальный слой | — |
| `./identity` | вывод состояния рейла и профиля, типы | `vue` |
| `./inertia` | адаптер над `usePage()` | `vue`, `@inertiajs/vue3` |
| `./playwright` | `loginAs`, `logout`, `credentialsFor` | `@playwright/test` |

Одноранговые зависимости, кроме `vue`, объявлены необязательными. Продукт
не на Inertia потребляет `./identity` напрямую и `@inertiajs/vue3` не ставит;
`./playwright` нужен только прогонам.

## Быстрый старт

```bash
npm install @verdeect/identity-nav-vue
```

Три шага, без которых рейл не заработает:

1. Импортировать стили: `@import '@verdeect/identity-nav-vue/style.css'`
   ([Установка](docs/installation.md)). Шрифта иконок пакет не требует:
   иконки пунктов приходят файлами, значки блока пользователя встроены.
2. Смонтировать **два** вида навигации — полосу и один мобильный — и передать
   в оба `currentUrl` ([Встраивание](docs/embedding.md)).
3. Написать правила переключения видов со своим порогом и **вне `@layer`**
   ([Оформление](docs/styling.md)).

### Какой компонент для чего

| Компонент | Где живёт | Когда показывается |
| --- | --- | --- |
| `CrossServiceRail` | самым внешним элементом оболочки, слева от навигации продукта | широкий экран |
| `CrossServiceMenu` | первым блоком выдвижного меню продукта | узкий экран, **вид 1** |
| `CrossServiceBar` | плашкой, прижатой к низу экрана | узкий экран, **вид 2** |

**Мобильные виды взаимоисключающие** — это два ответа на один вопрос, а не два
блока рядом. Плашка внизу подходит не всякой оболочке: она отнимает у
содержимого 84 px постоянно и спорит с собственной нижней панелью продукта.
Есть выдвижное меню — берите `CrossServiceMenu`; переходы между сервисами
часты — плашку. Пакет за продукт не выбирает.

Данные берутся из `useIdentity()` (Inertia) либо `useIdentityView()` (любой
другой стек) — [Состояние рейла](docs/state.md).

Пакет поставляется **исходниками**, без шага сборки: собирает их Vite продукта.

## Проверки

```bash
npm test
```

Четыре проверки: полнота словаря подписей, изоляция каталога компонентов
(включая условия «ядро разбирается без Inertia» и «конструкций бандлера
внутри нет»), типы исходников и наборов, и 26 наборов правил прямыми вызовами.

Браузер не поднимается ни одним набором: `@playwright/test` служит прогонщиком
Node. Отдельного прогонщика ради этого не заводится — Playwright уже нужен
входу `./playwright`.

**Разметку наборы пакета не проверяют** — прогонщик не разбирает `.vue`.
Что компоненты рисуют, проверяют браузерные сценарии продуктов
([Тестирование](docs/testing.md)).

## Происхождение эталона

Каталог компонентов и визуальный слой перенесены из репозитория
`verdeect-identity-service`, коммит `c3b7f14d6195e9abd9b88d0b5c249302aefee48c`
от 2026-09-08.

### Разбор расхождений при переносе

К моменту переноса файлы существовали в трёх копиях — эталон установки, копия
внутри composer-пакета и копия сервиса уборки. Расхождения разобраны по одному.

**Компоненты (`.vue`, `.ts`).** Эталон и копия сервиса совпадали знак в знак;
копия composer-пакета отстала на два коммита эталона и отброшена целиком.

**Визуальный слой (`style.css`).** Код совпадал: правки размеров рейла
в пикселях (кадры макета 2a и 2c) к моменту переноса были и в эталоне.
Расходился один докблок — о том, почему плашка иконки закреплена классом
предка. Взята формулировка эталона: она объясняет причину через порядок
загрузки файлов у произвольного продукта, тогда как формулировка сервиса
описывала расстановку файлов конкретной установки и в библиотеке была бы
неверна.

**Копий не осталось ни одной.** После перевода обоих продуктов проверено
поиском по трём рабочим деревьям: файлов компонентов, стилей рейла и класса
`cross-service-nav` вне этого пакета нет.

Вместе с компонентами сюда переехали и их проверки: полнота словаря, изоляция
каталога и правило подсветки текущего пункта. В продуктах остались только
проверки встраивания.

**Правки при переносе — только докблоки, ни одного правила стиля
и ни одной строки кода.** В `cross-service/index.ts` и в заголовке
`style.css` переезд в пакет описан как состоявшийся, а ссылка на проверку
изоляции указывает на `scripts/check-component-isolation.mjs` вместо
PHP-набора, которого в этом репозитории нет.
