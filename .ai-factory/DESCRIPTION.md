# @verdeect/identity-nav-vue

## Обзор

Библиотека Vue-компонентов кросс-сервисной навигации Verdeect Identity. Отдаёт
три вида навигации (`CrossServiceRail`, `CrossServiceMenu`, `CrossServiceBar`),
блок пользователя единого входа (`UserMenu`), их визуальный слой, вывод
состояния рейла, загрузку гостевого состава для лендингов без бэкенда
и Playwright-хелпер входа для браузерных прогонов.

**Это библиотека, а не приложение.** Пакет поставляется исходниками — `.vue`,
`.ts` и `.css` без шага сборки: интерфейс собирает Vite потребителя, а
`@vitejs/plugin-vue` обрабатывает `.vue` в зависимостях наравне со своими.
**Собственной зависимости от Vite у пакета нет ни одной** — ни в сборке,
ни в devDependencies, ни в коде: `import.meta.env` из каталога убран,
и условие 6a `check:isolation` не даёт завести его снова. Конструкции
бандлера существуют только внутри его сборки, а какой бандлер у потребителя,
пакет не знает.

**Каталог `src/cross-service` — эталон экосистемы.** Он перенесён из
репозитория `verdeect-identity-service` (коммит `c3b7f14`) и является
единственным источником истины: копий в продуктах не осталось ни одной. Правка
идёт сюда, потребители получают её обновлением зависимости.

## Два режима подключения

| | Продукт установки | Лендинг без бэкенда |
| --- | --- | --- |
| Кто | Приложение с серверной частью и входом через identity | Статический SPA без серверной части и без входа |
| Откуда данные | Бэкенд продукта (`verdeect/identity-laravel`) | Браузер напрямую из identity |
| Вход пакета | `./inertia` либо `./identity` | `./public` |
| Что показывается | Навигация по роли, шестерёнка настроек, `UserMenu` | Только гостевая навигация |
| Условие на стороне identity | Служебный клиент с областью `navigation:read` | Включена публичная операция `GET /api/public/navigation` |

Компоненты в обоих режимах одни и те же: второго комплекта для лендингов нет,
копия разошлась бы с эталоном на первой правке.

## Состав

- **Три вида навигации.** `CrossServiceRail` — полоса слева, десктоп;
  `CrossServiceMenu` — блок в выдвижном меню продукта; `CrossServiceBar` —
  плашка внизу экрана. Потребитель монтирует полосу и **один** мобильный вид —
  они взаимоисключающие. Каждый вид проставляет `data-placement`
  (`rail`, `overlay`, `bottom`), и переключение пишет таблица стилей
  потребителя.
- **Шестерёнка настроек** рисуется при непустом `profileUrl`: гостю установка
  адреса профиля не отдаёт, и отдельного признака входа нет.
- **Блок пользователя единого входа** — шапка профиля, «Профиль», пункты
  продукта, «Выход». Выход порождает событие `logout` и никуда не
  перенаправляет: у продуктов выход устроен по-разному.
- **Правило текущего пункта** (`currentItemId`) — двухъярусное: точное
  совпадение пути, затем запасное совпадение по хосту. Схема и хост обязательны
  на обоих ярусах, поэтому адрес открытой страницы передаётся абсолютным.
- **Словарь подписей** (`strings.ts`) — внутри каталога, потому что переезжает
  вместе с компонентами; языки установки — `ru` и `en`.
- **Вывод состояния рейла** (`useIdentityView`) — профиль, состав рейла, язык
  (профиль → свойства продукта → `ru`), признак непустого рейла и абсолютный
  `currentUrl`.
- **Адаптер Inertia** (`useIdentity`) — единственный файл пакета, импортирующий
  `@inertiajs/vue3`.
- **Адаптер лендинга** (`usePublicNavigation`) — загружает гостевой состав
  публичной операцией установки из браузера, перекладывает ответ в форму
  компонентов и отдаёт его тому же ядру с профилем `null`. При отказе — пустой
  рейл и причина (`disabled`, `rate_limited`, `unavailable`, `malformed`,
  `misconfigured`).
- **Вход в продукт для прогонов** (`loginAs`, `logout`, `credentialsFor`) —
  через реальную установку identity: PKCE, `state`, `nonce` и точное совпадение
  адреса возврата против двойника не проверяются.

## Стек

- **Язык:** TypeScript 5, режим `strict`, `noEmit`
- **Библиотека представления:** Vue 3.5, SFC `<script setup lang="ts">`
- **Оформление:** обычный CSS; цвета навигации постоянны, переменные темы
  продукта читает блок пользователя; препроцессора и утилитарных фреймворков нет
- **Прогонщик:** `@playwright/test` в роли прогонщика Node (браузер не
  поднимается ни одним набором пакета)
- **Проверка типов:** `vue-tsc --noEmit`
- **Сборка:** отсутствует намеренно
- **База данных, ORM, серверная часть:** отсутствуют — компоненты получают
  данные только props

## Шесть входов

| Вход | Содержимое | Зависимости | Режим |
| --- | --- | --- | --- |
| `.` | `CrossServiceRail`, `CrossServiceMenu`, `CrossServiceBar`, `UserMenu` и их типы | `vue` | оба |
| `./style.css` | визуальный слой | — | оба |
| `./identity` | вывод состояния рейла и профиля, типы | `vue` | продукт |
| `./inertia` | адаптер над `usePage()` | `vue`, `@inertiajs/vue3` | продукт |
| `./public` | `usePublicNavigation`, типы | `vue` | лендинг |
| `./playwright` | `loginAs`, `logout`, `credentialsFor` | `@playwright/test` | прогоны продукта |

Ядро отделено от адаптеров намеренно: правила вывода (абсолютный адрес страницы,
пустой рейл по умолчанию, порядок разрешения языка) принадлежат библиотеке,
а знание о схеме доставки данных — нет. Все одноранговые зависимости, кроме
`vue`, объявлены необязательными через `peerDependenciesMeta`.

## Архитектурные решения

**Изоляция каталога компонентов.** Внутри `src/cross-service` запрещены сетевые
обращения, браузерные хранилища, импорты кроме `vue` и локальных файлов, адреса
вида `http(s)://`, слово `token`, числовые пороги ширины, `matchMedia`
и `innerWidth`. Обращение к `document` допустимо только в файлах закреплённого
перечня с доводом; обращений к консоли нет ни одного, как и к `import.meta`.
Соблюдение проверяет `scripts/check-component-isolation.mjs`; тем же скриптом
проверяется, что ядро `src/identity` разбирается без `@inertiajs/vue3`.

**Сетевой запрос разрешён только адаптеру `./public`** (условие 11): у лендинга
нет серверной части, и данные рейла некому получить, кроме браузера. Прочие
запреты каталога на адаптер распространяются; ядро адаптер не импортирует
(условие 12).

**Пороги ширины принадлежат потребителю.** Ни одного числового порога в пакете
нет и заводить нельзя: каждый вид проставляет `data-placement`, а какой показать,
решает таблица стилей потребителя своим медиазапросом — тем же, на котором
переключается его собственная навигация.

**Данные приходят компонентам только props.** Порядок пунктов — как передан
(он задан реестром установки), формы имени приходят готовыми, иконки — файлами
по подписанной ссылке `iconUrl`.

**Токенов в пакете нет.** В режиме продукта схема Backend-for-Frontend
обязательна — токены живут на сервере продукта; в режиме лендинга публичная
операция токена не требует.

## Архитектура

Подробные правила — `.ai-factory/ARCHITECTURE.md`.
Образец: Explicit Architecture (Flat Vertical Slice) — порты и адаптеры
в миниатюре: ядро (`src/cross-service`, `src/identity`) не знает о схеме
доставки данных, `src/inertia`, `src/public` и `src/playwright` — адаптеры.

## Обязанности потребителя

Пакет намеренно не знает о хозяине, поэтому часть работы остаётся потребителю:
монтирование полосы и **одного** мобильного вида, правила переключения видов
со своим порогом и **вне `@layer`**, сдвиг вёрстки на
`--cross-service-rail-width`, абсолютный `currentUrl`, язык для гостя,
включение origin установки и хранилища иконок в `img-src`. Перечень для
продукта установки с разбором симптомов — `docs/checklist.md`; для лендинга —
`docs/landing.md` (там же `connect-src` и включение публичной операции
в установке).

## Проверки

`npm test` — четыре проверки подряд:

1. `check:strings` — полнота словаря подписей (состав ключей совпадает между
   языками, все используемые ключи объявлены, перечень языков совпадает с
   языками установки);
2. `check:isolation` — изоляция каталога компонентов, «ядро разбирается без
   Inertia» и границы адаптера публичной навигации;
3. `types:check` — `vue-tsc --noEmit`;
4. `test:unit` — 47 наборов прямыми вызовами: правило подсветки, разрешение
   языка, выбор подписей, разбор ответа и загрузка публичной навигации.

Браузер не поднимается ни одним набором. Отдельного прогонщика ради этого не
заводится: Playwright уже нужен входу `./playwright`.

## Связи экосистемы

Потребителей три вида: продукты установки `cleaner-service` и `identity-service`
(подключают пакет версией из npm, `^0.4.x`) и лендинги без бэкенда.

Операции установки, которые обслуживает пакет: `GET|POST /api/navigation` —
состав рейла для бэкенда продукта (служебный токен, область `navigation:read`);
`GET /api/public/navigation` — гостевой состав для лендинга без токена,
выключаемый развёртыванием (PRD навигации 5.8).

Парная composer-библиотека — `verdeect/identity-laravel`
(`github.com/smskin/verdeect-identity-laravel`, локально
`../verdeect-identity-laravel`). Между библиотеками контракт по данным рейла и
профиля (`NavItem` ↔ `NavigationData`, `IdentityProfile` ↔ `UserProfile`),
который в двух репозиториях расходится молча; договорённость — согласованный
minor.

Репозиторий — `github.com/smskin/verdeect-identity-nav-vue`, лицензия MIT.
Пакет опубликован в публичном npm как `@verdeect/identity-nav-vue`.

## Нефункциональные требования

- **Журналирование:** его нет и не должно быть — в консоль пакет не пишет
  вовсе. Отказ загрузки публичной навигации возвращается данными (`failure`),
  а не печатью.
- **Отказы:** непригодный адрес пункта — пропуск пункта, непригодный адрес
  страницы — `null` на всё правило подсветки; непригодный пункт ответа
  публичной операции пропускается; исключение наружу не выпускается.
  Единственные брошенные исключения — в `./playwright`, при незаполненном
  окружении прогона (`IDENTITY_BASE_URL`, `E2E_*_EMAIL`, `E2E_*_PASSWORD`):
  запасного адреса установки нет намеренно, иначе прогон молча ушёл бы на чужую
  систему.
- **Безопасность:** ни токенов, ни хранилищ; сетевой запрос — только в адаптере
  лендинга и без учётных данных; логотип и иконки грузятся с чужих доменов,
  поэтому их origin обязаны стоять в `img-src` потребителя.
- **Совместимость:** изменение контракта данных согласуется с
  `verdeect/identity-laravel` и выпускается согласованным minor; добавление
  входа без изменения контракта — patch.
