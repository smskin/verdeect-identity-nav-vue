# @verdeect/identity-integration-vue

## Обзор

Библиотека Vue-компонентов кросс-сервисной навигации Verdeect Identity. Отдаёт
продуктам установки рейл переходов между сервисами (`CrossServiceNav`), блок
пользователя единого входа (`UserMenu`), их визуальный слой, вывод состояния
рейла из свойств бэкенда и Playwright-хелпер входа для браузерных прогонов.

**Это библиотека, а не приложение.** Пакет поставляется исходниками — `.vue`,
`.ts` и `.css` без шага сборки: интерфейс собирает Vite потребителя, а
`@vitejs/plugin-vue` обрабатывает `.vue` в зависимостях наравне со своими.
`vite` в `devDependencies` стоит ровно ради типов `import.meta.env` для
`vue-tsc`, а не для сборки.

**Каталог `src/cross-service` — эталон экосистемы.** Он перенесён из
репозитория `verdeect-identity-service` (коммит `c3b7f14`) и является
единственным источником истины: копий в продуктах не осталось ни одной. Правка
идёт сюда, продукты получают её обновлением зависимости.

## Состав

- **Рейл кросс-сервисной навигации** — два представления одного содержимого:
  `placement="rail"` (полоса во всю высоту окна) и `placement="overlay"` (тот же
  перечень первым блоком выдвижного меню продукта). Продукт монтирует **оба**;
  `placement` обязателен и умолчания не имеет.
- **Блок пользователя единого входа** — шапка профиля, «Профиль», пункты
  продукта, «Выход». Выход порождает событие `logout` и никуда не
  перенаправляет: у продуктов выход устроен по-разному.
- **Правило текущего пункта** (`currentItemId`) — двухъярусное: точное
  совпадение пути, затем запасное совпадение по хосту. Схема и хост обязательны
  на обоих ярусах, поэтому адрес открытой страницы передаётся абсолютным.
- **Словарь подписей** (`strings.ts`) — внутри каталога, потому что переезжает
  вместе с компонентами; языки установки — `ru` и `en`.
- **Вывод состояния рейла** (`useIdentityView`) — профиль, состав рейла, язык из
  профиля, признак непустого рейла и абсолютный `currentUrl`.
- **Адаптер Inertia** (`useIdentity`) — единственный файл пакета, импортирующий
  `@inertiajs/vue3`.
- **Вход в продукт для прогонов** (`loginAs`, `logout`, `credentialsFor`) —
  через реальную установку identity: PKCE, `state`, `nonce` и точное совпадение
  адреса возврата против двойника не проверяются.

## Стек

- **Язык:** TypeScript 5, режим `strict`, `noEmit`
- **Библиотека представления:** Vue 3.5, SFC `<script setup lang="ts">`
- **Оформление:** обычный CSS с переменными темы продукта; препроцессора и
  утилитарных фреймворков нет
- **Прогонщик:** `@playwright/test` в роли прогонщика Node (браузер не
  поднимается ни одним набором пакета)
- **Проверка типов:** `vue-tsc --noEmit`
- **Сборка:** отсутствует намеренно
- **База данных, ORM, серверная часть:** отсутствуют — данные приходят только
  props, кэш живёт на бэкенде продукта

## Пять входов

| Вход | Содержимое | Зависимости |
| --- | --- | --- |
| `.` | `CrossServiceNav`, `UserMenu` и их типы | `vue` |
| `./style.css` | визуальный слой | — |
| `./identity` | вывод состояния рейла и профиля, типы | `vue` |
| `./inertia` | адаптер над `usePage()` | `vue`, `@inertiajs/vue3` |
| `./playwright` | `loginAs`, `logout`, `credentialsFor` | `@playwright/test` |

Ядро отделено от адаптера намеренно: правила вывода (абсолютный адрес страницы,
пустой рейл по умолчанию, язык из профиля) принадлежат библиотеке, а знание о
схеме доставки данных — нет. Продукт не на Inertia потребляет `./identity`
и `@inertiajs/vue3` не ставит. Все одноранговые зависимости, кроме `vue`,
объявлены необязательными через `peerDependenciesMeta`.

## Архитектурные решения

**Изоляция каталога компонентов.** Внутри `src/cross-service` запрещены сетевые
обращения, браузерные хранилища, импорты кроме `vue` и локальных файлов, адреса
вида `http(s)://`, слово `token`, числовые пороги ширины, `matchMedia` и
`innerWidth`. Обращение к `document` допустимо только в двух файлах по
закреплённому перечню с доводом; обращение к консоли — ровно одно, в
`strings.ts`, обёрнутое проверкой режима разработки. Соблюдение проверяет
`scripts/check-component-isolation.mjs`; девятым условием тот же скрипт
проверяет, что ядро `src/identity` разбирается без `@inertiajs/vue3`.

**Пороги ширины принадлежат продукту.** Ни одного числового порога в пакете нет
и заводить нельзя: `CrossServiceNav` проставляет на корневом элементе
`data-placement`, а какое из двух представлений показать, решает таблица стилей
продукта своим медиазапросом — тем же, на котором переключается его собственная
навигация. Порог, зашитый в пакет, уехал бы в продукт с другим порогом чужим.

**Данные приходят только props.** Порядок пунктов — как передан (он задан
реестром на бэкенде), инициалы и формы имени приходят готовыми, перечень иконок
компоненты не ведут: рассинхрон версий набора PrimeIcons штатен.

**Токенов в пакете нет.** Схема Backend-for-Frontend обязательна — они живут
только на сервере продукта.

## Архитектура

Подробные правила — `.ai-factory/ARCHITECTURE.md`.
Образец: Explicit Architecture (Flat Vertical Slice) — порты и адаптеры
в миниатюре: ядро (`src/cross-service`, `src/identity`) не знает о схеме
доставки данных, `src/inertia` и `src/playwright` — адаптеры.

## Обязанности встраивающего продукта

Пакет намеренно не знает о хозяине, поэтому часть работы остаётся продукту:
монтирование двух экземпляров рейла, правила переключения представлений со своим
порогом и **вне `@layer`**, сдвиг оболочки на `--cross-service-rail-width`,
сборка абсолютного `currentUrl`, включение origin установки в `img-src`,
подключение шрифта PrimeIcons и переменные темы. Полный перечень с разбором
симптомов — `docs/checklist.md`.

## Проверки

`npm test` — четыре проверки подряд:

1. `check:strings` — полнота словаря подписей (состав ключей совпадает между
   языками, все используемые ключи объявлены, перечень языков совпадает с
   языками установки);
2. `check:isolation` — изоляция каталога компонентов и «ядро разбирается без
   Inertia»;
3. `types:check` — `vue-tsc --noEmit`;
4. `test:unit` — правило подсветки текущего пункта прямыми вызовами, 16 наборов.

Браузер не поднимается ни одним набором. Отдельного прогонщика ради этого не
заводится: Playwright уже нужен входу `./playwright`.

## Связи экосистемы

Потребителей два: `cleaner-service` и `identity-service`, оба подключают пакет
ссылкой `file:` на соседний каталог. Рядом лежит парная composer-библиотека
`../identity-integration-php` — между ними контракт по данным рейла и профиля
(`NavItem` ↔ `NavigationData`, `IdentityProfile` ↔ `UserProfile`), который в двух
репозиториях расходится молча; договорённость — согласованный minor.

Репозиторий на `gitlab.mkomov.com` будет называться
`verdeect-identity-integration-vue`, первый тег — `v0.1.0`.

## Нефункциональные требования

- **Журналирование:** его нет и не должно быть — единственное обращение к
  консоли предупреждает о неизвестном языке и только при
  `import.meta.env.DEV`.
- **Отказы:** непригодный адрес пункта — пропуск пункта, непригодный адрес
  страницы — `null` на всё правило подсветки; исключение наружу не выпускается.
  Единственные брошенные исключения — в `./playwright`, при незаполненном
  окружении прогона (`IDENTITY_BASE_URL`, `E2E_*_EMAIL`, `E2E_*_PASSWORD`):
  запасного адреса установки нет намеренно, иначе прогон молча ушёл бы на чужую
  систему.
- **Безопасность:** ни токенов, ни хранилищ, ни сетевых обращений внутри
  компонентов; логотип грузится с чужого домена, поэтому origin установки
  обязан стоять в `img-src` продукта.
- **Совместимость:** изменение контракта данных согласуется с
  `../identity-integration-php` и выпускается согласованным minor.
