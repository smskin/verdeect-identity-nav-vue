## Задача одним абзацем

В тёмной теме продукта (owui-branding, класс `.app-dark` на `<html>`) рейл
и нижняя плашка остаются светлыми и выглядят чужеродно. Причина — решение
от 09.09.2026: цвета трёх видов навигации записаны литералами, чтобы рейл
выглядел одинаково во всех продуктах. Макет `Global Nav Bar.html` получил
раздел «5 · тёмная тема» (кадры 5a–5d) и таблицу «Токены: светлая → тёмная».
План сохраняет смысл прежнего решения — палитра по-прежнему **пакетная, одна
на все продукты**, продукт под себя её не подгоняет, — но делает её
двухвариантной: светлая как сейчас, тёмная по макету. Переключает её тот же
признак, которым продукт переключает свою тему.

## Принятые решения

| # | Решение | Почему |
| --- | --- | --- |
| 1 | Цвета видов выносятся в **приватные токены** `--cross-service-color-*` в `tokens.css`, а файлы видов читают только их | Тёмной теме иначе пришлось бы повторять каждый селектор с каждым состоянием в `dark.css`, и первый же новый селектор остался бы светлым молча. С токенами тёмная тема — один блок переопределений |
| 2 | Светлые значения токенов равны нынешним литералам **до цифры** | Светлая тема не меняется ни в одном продукте; дифф стилей видов — чистая замена литерала на `var()` |
| 3 | Тёмные значения — из таблицы макета и кадров 5a–5d, без подбора на глаз | Макет — источник истины для эталона. Там, где таблица молчит (нажатие, попап, заглушка, шов), берутся значения кадров 5b–5c |
| 4 | Признак тёмной темы — класс `.app-dark` **на любом предке**, по умолчанию на `<html>` | Этот класс ставит переключатель оболочки Sakai у обоих продуктов установки (`darkModeSelector: '.app-dark'`). `dark.css` уже опирается на него. Переопределения стоят на самом `.app-dark`, поэтому наследуются и в узел подсказки, вынесенный `Teleport`'ом в `body` |
| 5 | Токены — **не контракт с продуктом**. В документации сказано прямо: переопределять их продукту нельзя | Иначе вернулась бы проблема, ради которой принимали решение 09.09: рейл в каждом продукте свой. Переопределение технически возможно, но ломает узнавание, и отвечает за это продукт |
| 6 | Постоянные цвета (логотип, заливка заглушки текущего пункта `#8265ea` / `#fff`) — токены **без** приставки `-color-`: `--cross-service-brand`, `--cross-service-brand-contrast` | По макету они в обеих темах одинаковы. Тёмная пара для них была бы шумом, а набор задачи 8 сверяет пары только у `-color-*` |
| 7 | Элемент `./element` получает тёмную тему **атрибутом `theme="dark"`** на хосте, правилом `:host([theme='dark'])`. Свойства Vue не заводится | Теневой корень не видит класс на `<html>` продукта, а `:host-context()` не работает в Firefox и Safari. С атрибутом правило CSS работает даже без Vue-свойства, а свойство без отражения в атрибут правило бы не включало |
| 8 | `UserMenu` по-прежнему берёт поверхности и текст из **переменных темы продукта**. По макету (4b, 5d) у него меняется одно: раскрытый триггер подсвечивается акцентом (`--cross-service-color-current-bg`), шеврон — акцентным цветом | Блок стоит в шапке продукта, и выпадать из неё он не должен (`docs/styling.md`) — этот довод в силе. Кадры 4b и 5d совпадают с поверхностями Sakai по смыслу, а акцент открытого состояния — единственное, чего в реализации нет. **Это меняет вид раскрытого триггера и в светлой теме** (сейчас `--surface-hover`) — сверено с кадром 4b |
| 9 | Затемнение под всплывающим списком плашки в тёмной теме — 50 % (кадр 5c), в светлой остаётся 28 % | Таблица называет 32 % → 55 %, но 55 % относится к шторке (кадр 5b), которой в пакете нет. Кадр 5c показывает сам список плашки — 50 %. Светлое значение не трогаем (решение 2) |
| 10 | `dark.css` остаётся последним в `style.css`. Снятие тени остаётся только у меню пользователя, **с полосы оно снимается** | Порядок закреплён докблоком `style.css`. `box-shadow` полосы — не тень, а её разделитель справа (`nav-rail.css`); прежнее правило убирало край полосы, а в кадре 5a разделитель есть |
| 11 | Выпуск **0.4.8** (patch) | Правило `CHANGELOG.md` и `docs/contributing.md`: одинаковый minor у обеих библиотек интеграции; правка, не ломающая контракт, выходит patch. Диапазон `^0.4.4` у продуктов принимает выпуск без правки `package.json` |
| 12 | Проверка в owui-branding — **копией `src/` пакета поверх `node_modules`**, без `npm link` и без правки `package.json` / `vite.config` | Симлинк выводит пакет за корень Vite (`server.fs.allow`) и приносит второй экземпляр `vue` из `node_modules` пакета. Копия ничего не меняет в репозитории продукта и снимается `npm ci` |

## Объём и отложенное

**Входит:** токены цвета, перевод четырёх файлов видов на токены, тёмные
переопределения для `.app-dark` и `:host([theme='dark'])`, акцент раскрытого
триггера `UserMenu`, набор проверки пар, документация, журнал изменений,
версия 0.4.8, проверка на owui-branding.

**Отложено:**

- **Тема по `prefers-color-scheme`.** Тему выбирает продукт, пакет следует
  его признаку; своё решение по системной теме разошлось бы с переключателем
  продукта.
- **Подсказка в элементе `./element`.** Узел подсказки выносится `Teleport`'ом
  в `body` документа, за теневой корень, и стилей там нет ни в одной теме.
  Дефект прежний, к теме не относится.
- **Шторка продукта (кадр 5b целиком).** Фон и затемнение шторки принадлежат
  оболочке продукта; пакет отвечает только за блок `CrossServiceMenu` внутри неё.
- **Выпуск и обновление зависимости в owui-branding** — после ревью, отдельным
  шагом владельца.
