Ветка: `feature/web-component-element`
Создан: 2026-09-28
Выпуск: 0.4.7

## Original Request

full — Репозиторий: /Users/smskin/PhpstormProjects/verdeect/verdeect-identity-nav-vue (работать в нём, не в owui). Задача: добавить в @verdeect/identity-nav-vue собранный web component (custom element) для продуктов не на Vue (первый потребитель — Open WebUI на Svelte). Новый вход пакета со сборкой перед публикацией (Vue runtime внутри бандла, defineCustomElement, стили внутри shadow DOM, цвета через CSS-переменные хоста). Элемент отображает CrossServiceRail (десктоп, слева) или CrossServiceBar (мобила, снизу); вид выбирает продукт атрибутом placement — порог ширины остаётся у продукта. Данные (items, logoUrl, profileUrl, currentUrl, locale) задаются свойствами элемента. Нижняя панель должна уметь прятаться (атрибут/свойство hidden-режим, которым продукт управляет при открытой клавиатуре) и публиковать высоту в --cross-service-bar-height на document. Поправить правила: SKILL.md verdeect-cross-service, ARCHITECTURE.md, DESCRIPTION.md, AGENTS.md, check-component-isolation — разрешить шаг сборки только для этого входа; исходный вход остаётся без сборки. Добавить сборку в .github/workflows/publish.yml перед npm publish. Документация: новый docs/web-component.md + упоминания в README и installation.md. CHANGELOG, версия 0.5.0.

## Решения и отступления от запроса

- **Версия 0.4.7, а не 0.5.0.** `CHANGELOG.md` и `docs/contributing.md` держат
  одинаковый minor у пакета и парной `verdeect/identity-laravel`. Контракт
  данных не меняется, поэтому новый вход выходит patch-версией, и выпускать
  PHP-библиотеку не нужно.
- **Исключение из запрета на сборку узкое.** Сборка разрешена только входу
  `./element`, только в каталоге `src/element/`, и только в момент упаковки.
  Входы `.`, `./style.css`, `./identity`, `./inertia`, `./public` и
  `./playwright` по-прежнему поставляются исходниками. Каталог
  `src/cross-service` не получает ни одного нового импорта и ни одной
  конструкции бандлера.
  Прежний довод против бандла из `docs/installation.md` («ни один потребитель
  не потребляет его без Vite») больше не верен: появился потребитель
  на Svelte.
- **Сборка идёт на `prepack`, а не на `prepare`.** Установка из git не должна
  тянуть сборку. Следствие: вход `./element` есть только у пакета из реестра
  npm, и это фиксирует документация.
- **Vue находится внутри бандла.** Потребитель не ставит `vue` для этого входа.
  Поэтому одноранговой зависимости у входа нет, и правило ENTRIES.md «вход без
  объявленной зависимости не заводится» к нему не относится. Это
  документируется явно.
- **Порога ширины нет и в элементе.** Вид задаёт продукт атрибутом `placement`
  (`rail` или `bottom`). Элемент монтирует ровно один вид и не обращается
  ни к `matchMedia`, ни к `innerWidth`, ни к `ResizeObserver` сам по себе:
  наблюдение за высотой у плашки остаётся прежним.
- **Вид `overlay` (`CrossServiceMenu`) элемент не отдаёт.** Блок в выдвижном
  меню требует монтирования внутрь чужой разметки. Потребителю не на Vue
  доступны полоса и плашка. Если понадобится третий вид, он добавляется
  отдельным выпуском.
- **Скрытие при открытой клавиатуре — стандартный атрибут `hidden` на элементе.**
  Его ставит и снимает продукт. Стили элемента гарантируют, что хост с `hidden`
  не отображается. Плашка при этом не меняется: её наблюдатель размеров видит
  нулевую высоту, `barHeight.ts` снимает `--cross-service-bar-height`,
  и отступ содержимого у продукта исчезает сам. Отдельного свойства и события
  не заводится.
- **Shadow DOM.** Визуальный слой `./style.css` встраивается в теневой корень
  элемента. Переменные темы продукта (`--surface-card`, `--primary-color`
  и так далее) наследуются сквозь теневую границу, поэтому тема продукта
  работает без правок. Переменные, объявленные в `tokens.css` на `:root`,
  внутрь теневого корня не попадают. Поэтому селектор блока переменных
  расширяется до `:root` и `:host`. Для прежних потребителей поведение
  не меняется: `:host` вне теневого корня не совпадает ни с чем.
- **Ширину полосы продукт с элементом берёт запасным значением.**
  `--cross-service-rail-width`, объявленная внутри теневого корня, снаружи
  не видна. Продукт сдвигает оболочку правилом с запасным значением
  переменной, и документация называет это значение. Записывать переменную
  в документ из элемента не нужно: в отличие от высоты плашки, ширина
  полосы постоянна.
- **Тёмная тема блока пользователя (`.app-dark …`) внутри элемента
  не действует.** Блок пользователя элемент не отдаёт, а цвета полосы
  и плашки идут от переменных продукта.

## Отступления при реализации

- **Задача 2.** Вместо `src/element/env.d.ts` создан `src/element/types.ts`
  с типами `ElementPlacement` и `IdentityNavElementProps`. Визуальный слой
  подключается `@import '../style.css'` в стилях `IdentityNav.ce.vue`, и Vite
  разворачивает его при сборке. Поэтому импорт `?inline` и объявление модуля
  для него не понадобились. Тот же приём снял и вторую проблему: ключ
  `styles` в дополнительных параметрах `defineCustomElement` затирал бы
  стили компонента.
- **Задача 4.** Вход только превращает компонент в элемент и регистрирует тег;
  стили приходят из компонента. Разрешённые импорты условия 13: `vue`, `./*`,
  `../cross-service` и `../style.css`. Условие 14 запрещает вне `src/element`
  любые импорты с `?`.
- **Тема.** Цвета навигации в пакете постоянные (`docs/styling.md`), поэтому
  в документацию попало «рейл одинаков в любом продукте», а не «цвета
  от темы продукта».
- **Задача 8.** Страница-образец проверена в браузере. Результаты:
  - `rail` — полоса, логотип, подсветка, заглушка буквой, шестерёнка;
  - `bottom` — плашка, `--cross-service-bar-height` 49px;
  - `hidden` — элемент скрыт, переменная снята, после снятия атрибута
    вернулась;
  - пустой `items` — ничего не отрисовано.
