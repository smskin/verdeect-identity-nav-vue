## Settings

- **Логирование:** нет — по правилу пакета в консоль не пишется ничего (`.ai-factory/rules/base.md`, «Журналирование»); отказ загрузки выражается **состоянием**, которое композиция возвращает

## Задача одним абзацем

Лендинги установки — статические SPA без серверной части. Держать секрет клиента
они не могут, поэтому закрытая операция `GET /api/navigation` им недоступна.
identity заводит публичную операцию `GET /api/public/navigation` (план
`identity-service/.ai-factory/plans/feature-public-guest-navigation.md`). Пакету
нужен **вход-адаптер**, который загружает этот ответ из браузера и отдаёт его
**тем же** компонентам `CrossServiceRail`, `CrossServiceMenu`, `CrossServiceBar`.
Второго комплекта компонентов не заводится. Вместе с входом документация явно
описывает **два режима подключения** пакета.

## Принятые решения

| # | Решение | Почему |
| --- | --- | --- |
| 1 | Второго комплекта компонентов **нет**; лендинг монтирует те же три вида | Виды уже работают без пользователя: `UserMenu` — отдельный компонент, шестерёнка не рисуется без `profileUrl`. Копия разошлась бы с эталоном на первой правке — ровно та беда, из-за которой пакет существует (`docs/contributing.md`) |
| 2 | Новый вход `./public`, каталог `src/public/` — **адаптер доставки данных**, как `./inertia` | Правило «компоненты в сеть не ходят» сохраняется. Сетевой запрос живёт в адаптере, как знание о `usePage()` живёт в `./inertia` |
| 3 | Композиция строит результат **через ядро** — `useIdentityView` с профилем `null` | Абсолютный `currentUrl`, порядок разрешения языка и признак непустого рейла уже закреплены в ядре. Второе воплощение в адаптере запрещено `.ai-factory/ARCHITECTURE.md` («правило вывода в адаптере») |
| 4 | Обёртки-компонента нет; мобильный вид выбирает разработчик лендинга | Решение пользователя. Пакет и сейчас не выбирает вид за продукт |
| 5 | Отказ загрузки — пустой рейл плюс **причина** в возвращаемом значении: `disabled`, `rate_limited`, `unavailable`, `malformed`, `misconfigured` | Журналирования в пакете нет, а понять, почему рейла нет, разработчику нужно. Причина — данные, а не консоль |
| 6 | Собственного кэша нет — ни в памяти, ни в браузерных хранилищах | Ответ кэширует identity и браузер по `Cache-Control`. Хранилища запрещены условием 2 изоляции, и правило распространяется на новый вход |
| 7 | Запрос без учётных данных (`credentials: 'omit'`), без параметров строки запроса | CORS identity разрешает любой origin **без** учётных данных. Любой параметр строки запроса операция отклоняет `400` |
| 8 | Загрузка начинается при монтировании и прерывается при размонтировании | При отрисовке на сервере запрос бесполезен. Ответ, пришедший в размонтированный компонент, писал бы в мёртвое состояние |
| 9 | Разборщик и загрузчик — отдельные файлы, проверяемые прямыми вызовами; сама композиция наборами не покрывается | Прогонщик не монтирует компоненты, а хуки жизненного цикла вне компонента не выполняются. Вся логика вынесена из композиции туда, где её можно вызвать |
| 10 | Выпуск 0.4.2 без ломающих изменений | Добавляется вход и тип; существующие входы не меняются. Patch, а не minor: правило «одинаковый minor у обеих библиотек интеграции» (`docs/contributing.md`) — парный `verdeect/identity-laravel` на 0.4, а контракт с ним вход не затрагивает; на 0.x диапазон `^0.4.x` продуктов не пропускает смену minor, и 0.5.0 потребовал бы правки `package.json` без ломающего изменения |

## Два режима подключения — как это подаётся в документации

| | Режим «Продукт установки» | Режим «Лендинг без бэкенда» |
| --- | --- | --- |
| Кто | Приложение с серверной частью и входом через identity | Статический SPA без серверной части и без входа |
| Данные | Бэкенд продукта (`verdeect/identity-laravel`) | Браузер напрямую из identity |
| Вход пакета | `./inertia` либо `./identity` | `./public` |
| Состав | Навигация по роли, шестерёнка, `UserMenu` | Только гостевая навигация |
| Условие на стороне identity | Служебный клиент области `navigation:read` | Включена публичная операция |

Таблица стоит **в начале README** и повторяется в `docs/installation.md`. Каждая
страница `docs/` в первом абзаце называет, к какому режиму относится.
Для лендинга заводится отдельная страница `docs/landing.md`.

## Cross-Plan Dependencies

Настоящий план потребляет контракт плана
`identity-service/.ai-factory/plans/feature-public-guest-navigation.md`
(PRD навигации 5.3 и 5.8).

| Что | Источник | Ожидаемое значение |
| --- | --- | --- |
| Адрес | задачи 2, 11 плана identity | `GET <identity>/api/public/navigation` |
| Тело `200` | задачи 2, 10 плана identity; PRD 5.3 | объект с `items` (массив `{id, name, url, icon_url, order}`) и `logo_url`; `profile_url` нет |
| Выключенная операция | задачи 7, 8 плана identity | `404 {"error":"not_found"}` |
| Посторонний параметр | задача 10 плана identity | `400 unknown_filter` |
| Частота | задача 9 плана identity | `429` с `Retry-After` |
| CORS | решение 9 плана identity | чтение с любого origin без учётных данных |

**Перед задачей 5 сверить контракт с фактической реализацией identity.** Если
план identity ещё не слит, сверяться с PRD навигации 5.8 и отметить расхождение
в задаче.

**Порядок выпуска.** Пакет можно выпустить раньше identity: вход безвреден
и при отсутствии операции отдаёт пустой рейл с причиной `disabled`. Но
документация обязана назвать минимальную версию identity с публичной операцией.

## Объём и отложенное

**Входит:** вход `./public` (типы, разборщик, загрузчик, композиция), условие
изоляции, наборы, документация двух режимов и актуализация всех описаний
пакета, выпуск 0.4.2.

**Отложено:**
- **Повтор запроса после `429` или сетевого отказа.** Лендинг показывает страницу
  без рейла; повтор по таймеру без просьбы продукта нагрузил бы identity ровно
  тогда, когда она просит сбавить частоту.
- **Кэш ответа в пакете** — решение 6.
- **Браузерная проверка встраивания.** Её делает лендинг-потребитель, как
  продукты делают сейчас (`docs/testing.md`).

### Phase 2 — Контракт и разбор ответа

- [ ] **2. Типы входа**
  **Файл:** `src/public/types.ts` (CREATE)
  **Skill:** `create-ts-file` (CREATE); свериться с `verdeect-cross-service`
  **Что объявить**, интерфейсами с полями `readonly`, без индексных сигнатур:

    - адрес установки identity — строка, origin без завершающей косой;
    - язык подписей — функция, возвращающая строку;

  - **Перечень причин отказа** объединением строк: `disabled`, `rate_limited`,

    - `rate_limited` — превышен порог по адресу;

    либо отказ с причиной. Отдельный исход для прерывания при размонтировании
    наружу не отдаётся.
  - **Возвращаемое значение композиции:** состав рейла (`CrossServiceData`
    из `../identity`), язык, признак непустого рейла, абсолютный адрес
    страницы, признак загрузки, причина отказа или `null`. Профиля в нём нет:
    в этом режиме его не бывает.
  **Логирование:** нет.

- [ ] **3. Разборщик ответа**
  **Файл:** `src/public/parseResponse.ts` (CREATE)
  **Skill:** `create-ts-file` (CREATE)
  Чистая функция: на входе значение, полученное разбором JSON, неизвестного типа;
  на выходе разобранный ответ из задачи 2 либо `null`.

  **Правила:**
  - не объект, либо `items` не массив — `null`;
  - пункт пропускается, если одно из условий не выполнено:
    - `id` — непустая строка;
    - `url` — строка;
    - `order` — число;
    - `name` — объект, у которого хотя бы одно значение — непустая строка;
      нестроковые значения отбрасываются;
  - `icon_url` — строка, иначе пустая строка: пустая ссылка законна и даёт
    заглушку первой буквой;
  - `logo_url` — строка, иначе пустая строка;
  - поля пункта перекладываются в `NavItem`: `icon_url` становится `iconUrl`,
    прочие — как есть;
  - порядок пунктов сохраняется как пришёл и не пересортировывается:
    его задаёт реестр;
  - посторонние поля (`profile_url`, всё неизвестное) игнорируются.

  **Докблок:** почему пропуск, а не отказ (правило пакета: одна кривая запись
  не гасит навигацию). Почему разборщик свой, а не приведение типа: ответ
  приходит из сети, и приведение заглушило бы расхождение контракта.
  **Логирование:** нет.
  **Зависит от:** 2.

### Phase 3 — Загрузка и композиция

- [ ] **5. Загрузчик**
  **Файл:** `src/public/loadPublicNavigation.ts` (CREATE)
  **Skill:** `create-ts-file` (CREATE)
  Асинхронная функция. **Принимает:** адрес установки, реализацию `fetch`
  и сигнал прерывания. Реализация передаётся параметром ради прямых вызовов
  в наборах; композиция передаёт глобальную. **Отдаёт** результат загрузки
  из задачи 2.

  **Порядок:**
  1. Разобрать адрес установки. Непригодный адрес или схема, отличная
     от `http:` и `https:`, — отказ `misconfigured` без запроса.
  2. Собрать адрес операции: origin установки плюс путь
     `/api/public/navigation`. Завершающие косые адреса установки срезаются,
     путь и строка запроса адреса установки не используются.
  3. Запрос `GET` с заголовком `Accept: application/json`, без учётных данных,
     без параметров, с переданным сигналом.
  4. Прерывание сигналом — отдельный исход, композиция его игнорирует. Прочее
     исключение запроса — отказ `unavailable`.
  5. Код `404` — `disabled`; `429` — `rate_limited`; иной код вне `2xx` —
     `unavailable`.
  6. Тело не разбирается как JSON — `malformed`.
  7. Разборщик задачи 3 вернул `null` — `malformed`, иначе успех.

  **Отказы не бросаются:** функция всегда возвращает значение.
  **Докблок:** почему `404` означает выключенную операцию, а не ошибку адреса
  (контракт identity), и почему учётные данные не отправляются (решение 7).
  **Логирование:** нет — решение 5.
  **Зависит от:** 2, 3.

- [ ] **6. Наборы загрузчика**
  **Файл:** `tests/loadPublicNavigation.spec.ts` (CREATE)
  **Skill:** `create-ts-file` (CREATE)
  Подменная реализация `fetch` — функция набора, возвращающая заданный ответ
  либо бросающая. Сеть не используется.

  **Сценарии:**
  1. `200` с телом по контракту — успех с разобранными пунктами.
  2. Запрос уходит на `<origin>/api/public/navigation` методом `GET`, без учётных
     данных, без строки запроса, с `Accept: application/json`.
  3. Адрес установки с завершающей косой и с путём — запрос всё равно
     на origin плюс путь операции.
  4. Непригодный адрес установки и адрес со схемой `ftp:` — `misconfigured`,
     подменная реализация не вызвана.
  5. `404` — `disabled`.
  6. `429` — `rate_limited`.
  7. `500` и `400` — `unavailable`.
  8. Исключение сети — `unavailable`.
  9. Прерывание сигналом — исход прерывания, а не отказ.
  10. Тело не JSON — `malformed`.
  11. JSON не по контракту — `malformed`.
  **Зависит от:** 5.

  **Файл:** `src/public/usePublicNavigation.ts` (CREATE)
  **Skill:** `create-ts-file` (CREATE); свериться с `vue-best-practices` (composables)
  Функция `usePublicNavigation`. **Принимает** опции задачи 2, **отдаёт**

  **Вывод через ядро.** Вызвать `useIdentityView` и передать ему:

  **Жизненный цикл:**

  - в любом исходе, кроме прерывания, признак загрузки становится ложным;

  - почему путь без опции не следит за маршрутизатором лендинга: окно
    читается при каждом вычислении, но вычисление не зависит от реактивного
    источника; лендинг с маршрутизатором передаёт путь опцией;
  - почему загрузка при монтировании (решение 8);
  - почему наборов у композиции нет (решение 9).

  **Логирование:** нет.
