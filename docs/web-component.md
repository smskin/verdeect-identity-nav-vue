# Пользовательский элемент для продуктов не на Vue

Вход `./element` отдаёт рейл кросс-сервисной навигации готовым
пользовательским элементом `<verdeect-identity-nav>`. Он нужен продукту,
которому исходники `.vue` взять нечем: интерфейс на Svelte (Open WebUI),
React или страница без сборщика. Продукты на Vue по-прежнему подключают
компоненты входа `.` — элемент им не нужен.

Внутри элемента те же компоненты `CrossServiceRail` и `CrossServiceBar`,
тот же визуальный слой и те же правила подсветки. Различается только
упаковка: Vue лежит внутри файла, стили — в теневом корне элемента.

Данные элементу, как и продукту установки на Vue, готовит **бэкенд продукта**:
служебным клиентом с областью `navigation:read` он запрашивает у identity
состав для вошедшего пользователя и отдаёт его своей странице. Сам элемент
в сеть не ходит, токенов в браузере нет.

## Что элемент умеет и чего не умеет

| Есть | Нет |
| --- | --- |
| полоса слева (`placement="rail"`) | блока в выдвижном меню (`CrossServiceMenu`): теневой корень не попадает в чужую разметку |
| плашка внизу (`placement="bottom"`) с переменной высоты | блока пользователя (`UserMenu`): у продукта своё меню и свой выход |
| скрытие атрибутом `hidden` | загрузки данных: их передаёт продукт |
| светлая и тёмная палитра (`theme`) | подгонки цветов под палитру продукта |
| регистрация тега и экспорт конструктора | входа при установке из git: файл собирается при упаковке пакета |

## Подключение

Файл `dist/element.js` есть только у пакета из реестра npm: он собирается
на `prepack`, а в git не хранится.

```bash
npm install @verdeect/identity-nav-vue
```

Файл — самодостаточный ES-модуль без внешних импортов. Скопируйте его
в статику продукта и подключите модулем:

```html
<script type="module" src="/static/identity-nav.js"></script>

<verdeect-identity-nav placement="rail"></verdeect-identity-nav>
```

Путь внутри пакета — `node_modules/@verdeect/identity-nav-vue/dist/element.js`,
а в сборщике он доступен импортом `@verdeect/identity-nav-vue/element`.
Одноранговая зависимость `vue` ставится вместе с пакетом, но элементу она
не нужна: Vue уже внутри файла.

Модуль регистрирует тег сам и не падает, если загружен дважды. Чтобы
зарегистрировать элемент под своим именем, возьмите конструктор
`IdentityNavElement` из того же модуля.

## Данные

Данные передаются **свойствами** элемента в том же формате, что и props
компонентов (`docs/embedding.md`). Строки можно передавать и атрибутами,
массив — только свойством.

| Свойство | Атрибут | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- | --- |
| `placement` | `placement` | `'rail'` \| `'bottom'` | `'rail'` | какой вид монтировать |
| `items` | — | `NavItem[]` | `[]` | пункты рейла, как пришли от бэкенда |
| `locale` | `locale` | `string` | `'ru'` | язык подписей |
| `currentUrl` | `current-url` | `string` | адрес при монтировании | **абсолютный** адрес текущей страницы |
| `profileUrl` | `profile-url` | `string` | — | шестерёнка профиля; пусто — шестерёнки нет |
| `logoUrl` | `logo-url` | `string` | `''` | логотип установки над полосой |
| `logoHeight` | `logo-height` | `string` | — (квадрат 64px) | высота плитки логотипа; как у продуктов на Sakai — `56px` (их `4rem` при корне 14px). Задавайте пикселями: `rem` считается от корня вашего документа |
| `theme` | `theme` | `'light'` \| `'dark'` | — (светлая) | палитра навигации; переключайте вместе со своей темой — [Тёмная тема](#тёмная-тема) |

Поле иконки пункта называется `iconUrl`. Бэкенд identity отдаёт его как
`icon_url`, и переименовать его должен сам продукт.

**`currentUrl` обновляйте при каждом переходе.** SPA-продукт элемент
не перемонтирует, и значение по умолчанию, вычисленное при монтировании,
оставило бы подсветку на первой открытой странице.

Пустой `items` не рисует ничего: ни пунктов, ни логотипа, ни плашки.

## Какой вид показать

Порога ширины в элементе нет, как нет его и во всём пакете. Какой вид
показать, решает продукт. Порог должен совпадать с порогом его собственной
навигации:

```js
const nav = document.querySelector('verdeect-identity-nav');
const narrow = window.matchMedia('(max-width: 767px)');
const apply = () => nav.setAttribute('placement', narrow.matches ? 'bottom' : 'rail');

narrow.addEventListener('change', apply);
apply();
```

Одновременно смонтирован ровно один вид.

## Место под навигацию

Оба вида закреплены `position: fixed`, а сам элемент места в разметке
не занимает. Место под навигацию отводит продукт.

- **Полоса** шириной `64px` стоит у левого края. Переменная
  `--cross-service-rail-width` объявлена внутри теневого корня, и снаружи
  её не видно. Сдвигайте оболочку правилом
  `var(--cross-service-rail-width, 64px)`: запасное значение и есть ширина
  полосы.
- **Плашка**, пока видна, пишет свою высоту в `--cross-service-bar-height`
  на корне документа. Отступ снизу у прокручиваемого контейнера продукта:
  `padding-bottom: var(--cross-service-bar-height, 0px)`. Контейнер высотой
  во весь экран уменьшайте на ту же величину. Тогда поле ввода, прижатое
  к низу, встанет над плашкой.

## Скрытие при открытой клавиатуре

Экранная клавиатура поднимает закреплённую плашку и зажимает её между собой
и полем ввода. Прятать плашку, пока клавиатура открыта, — обычная практика
для нижних вкладок. Для этого у элемента есть стандартный атрибут `hidden`:

```js
input.addEventListener('focus', () => { nav.hidden = true; });
input.addEventListener('blur', () => { nav.hidden = false; });
```

Скрытый элемент не отрисовывается. Плашка видит нулевую высоту и снимает
`--cross-service-bar-height`, поэтому отступ содержимого исчезает сам.
Когда атрибут снят, переменная возвращается.

## Тема

Стили продукта в теневой корень не проникают, поэтому сброс Tailwind
и глобальные правила рейл не задевают. То, что продукты на Sakai дают рейлу
своей страницей (`box-sizing: border-box`, сброс отступов и ссылок, шрифт
14px с межстрочным 1.2, цвет текста), элемент задаёт себе сам: рейл выглядит
так же, как в identity-service, на странице с любыми глобальными стилями.
Шрифт Instrument Sans элемент не загружает — если его нет у продукта,
сработает запасной `ui-sans-serif` / `system-ui`.

**Цвета полосы и плашки — палитра пакета**, как и у продукта на Vue: рейл —
это навигация установки, и выглядеть он должен одинаково во всех продуктах.
Подгонять его под палитру продукта нечем, и это решение пакета, а не
ограничение элемента (`docs/styling.md`, «Переменные оформления»). Слой
`--cross-service-bar-z-index` продукт при необходимости уточняет на самом
элементе: переменные наследуются сквозь теневую границу.

### Тёмная тема

**У элемента есть тёмная палитра, и включает её свойство `theme`.** Класс
тёмной темы продукта на `<html>` в теневой корень не виден, поэтому тему
элементу передают явно — в разметке либо из кода:

```html
<verdeect-identity-nav placement="rail" theme="dark"></verdeect-identity-nav>
```

```js
const nav = document.querySelector('verdeect-identity-nav');

nav.theme = 'dark';   // тёмная
nav.theme = 'light';  // светлая
```

Свойство и атрибут равносильны: значение свойства отражается в атрибут
`theme`, по которому палитру и включает правило CSS. Без значения
и с любым, кроме `dark`, палитра светлая.

Переключайте тему элемента **там же, где переключаете свою**, иначе они
разойдутся:

```js
function applyTheme(dark) {
    document.documentElement.classList.toggle('dark', dark);

    for (const nav of document.querySelectorAll('verdeect-identity-nav')) {
        nav.theme = dark ? 'dark' : 'light';
    }
}
```

Продукт, который следует системной теме, передаёт её так же:

```js
const scheme = window.matchMedia('(prefers-color-scheme: dark)');
const apply = () => applyTheme(scheme.matches);

scheme.addEventListener('change', apply);
apply();
```

Значения палитры — в [Оформлении](styling.md#тёмная-тема).

## Политика содержимого

Иконки пунктов и логотип загружаются по подписанным ссылкам. Добавьте
в `img-src` origin установки identity и origin хранилища иконок, как
и у продукта на Vue (`docs/checklist.md`). Сам элемент в сеть не ходит.
