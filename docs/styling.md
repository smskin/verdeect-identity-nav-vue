# Оформление

Страница для **обоих режимов**. Визуальный слой приходит одним файлом; порог
переключения и сдвиг оболочки пишет потребитель — продукт установки или
лендинг.

```css
/* resources/css/app.css продукта */
@import '@verdeect/identity-nav-vue/style.css';
```

## Порогов ширины в пакете нет ни одного

И заводить их нельзя. Порог принадлежит навигации продукта: собственного
мобильного режима у рейла нет, он переключается **вместе** с навигацией
хозяина. Константа «чтобы не забыть значение», заведённая в пакете, уехала бы
в продукт с другим порогом.

Каждый вид проставляет на корневом элементе `data-placement` — `rail`
у `CrossServiceRail`, `overlay` у `CrossServiceMenu`, `bottom`
у `CrossServiceBar`, — а решает продукт:

```css
@media (min-width: 992px) {
    [data-placement='overlay'] {
        display: none;
    }
}

@media (max-width: 991px) {
    [data-placement='rail'] {
        display: none;
    }

    /* На узком экране краткая форма имени прячется. */
    .cross-service-user__short-name {
        display: none;
    }
}
```

Числа берите те же, на которых переключается ваша навигация. Разойдясь, они
дадут либо два видимых вида, либо ни одного.

Макет навигации рекомендует **1024 px**, но это рекомендация, а не требование
пакета: совпадение с вашей навигацией важнее совпадения с макетом.

Смонтировав `CrossServiceBar` вместо `CrossServiceMenu`, целитесь
в `[data-placement='bottom']` — правило то же.

## Плашка внизу экрана

**Плашку к нижнему краю окна прижимает пакет.** С 0.4.5 компонент рисуется
`position: fixed` у нижнего края, отводит безопасную зону устройства и лежит
на слое `var(--cross-service-bar-z-index, 1000)`. Писать это правило у себя
больше не нужно — а написанное прежде следует удалить: оно совпадает
с пакетным по значениям ровно до первой правки пакета.

**Вам остаётся отступ содержимого.** Плашка вынута из потока документа,
и содержимое её не замечает: без отступа последние строки и подвал уйдут
под неё. Какой узел вашей оболочки прокручивается, пакет не знает, поэтому
отступ отводите сами — **высоту для него сообщает плашка**:

```css
/* Прокручиваемый контейнер вашей оболочки. */
.layout-main-container {
    padding-bottom: var(--cross-service-bar-height, 0px);
}
```

Правило **безусловное**, и медиазапрос ему не нужен: переменную ставит
смонтированная и видимая плашка. Скрыли её своим порогом, или состав пунктов
пуст, — переменной нет, и запасной ноль отдаёт содержимому всё место.

**Запасное значение `0px` обязательно.** Без него объявление с несуществующей
переменной недействительно, и отступ на широком экране окажется таким, каким
его оставила ваша оболочка, — чаще всего никаким.

**Монтируйте плашку в корень оболочки**, как и полосу. Закреплённый узел
считается от окна, только если ни один предок не задаёт `transform`, `filter`,
`perspective` или `contain: paint`; внутри такого предка плашка прижмётся
к нему — её видно посреди страницы либо она уезжает при прокрутке.

**Высоту числом не повторяйте.** На обычном экране она равна 49 px (кнопка
44 px — наименьшая область касания по WCAG 2.5.5, поля 2 + 2 px, верхняя
граница 1 px) плюс безопасная зона устройства, но это подробность оформления
пакета: он вправе её изменить, а вы вправе уточнить геометрию своей таблицей
стилей — плашка измеряет **настоящий отрисованный узел** и сообщает
получившееся.

### Слой

Умолчание — 1000, тот же, что у полосы: выше боковой навигации оболочки Sakai
(999) и её затемнения (998), потому что переход между продуктами обязан
оставаться доступным при раскрытом меню продукта.

Оговорка: у наложений PrimeVue (`overlay`) умолчание тоже 1000, и порядок
между ними решает порядок в документе. Нужен другой слой — уточните его
переменной, не перебивая правило:

```css
:root {
    --cross-service-bar-z-index: 900;
}
```

### Когда плашку ставит оболочка

Если оболочка размещает плашку сама (собственная нижняя панель, встроенный
контейнер), отключите закрепление пропом:

```vue
<CrossServiceBar :items="items" :locale="locale" positioning="static" />
```

Плашка останется в потоке документа там, где смонтирована, а высоту переменной
будет сообщать по-прежнему: отступ содержимому нужен оболочке независимо
от того, кто плашку закрепил.

## Правила переключения стоят вне `@layer`

**Это не стилистическое предпочтение.** Неслоистое объявление сильнее
слоистого при любой избирательности. Если оболочка продукта объявлена
неслоисто (так устроен Sakai), а ваши правила окажутся внутри слоя, они
проиграют — и оба представления рейла будут видны одновременно.

Держите эти три правила вне `@layer` и рядом с порогом навигации, чтобы
совпадение значений было видно глазом.

## Сдвиг оболочки

Пример ниже — для оболочки Sakai, на которой собраны продукты установки.
Сдвиг обычной вёрстки лендинга — в [Лендинге без бэкенда](landing.md#порог-и-сдвиг-вёрстки).

Рейл лежит `position: fixed` слева, шириной `--cross-service-rail-width`
(64px), с `z-index: 1000`. Оболочка продукта сдвигается вправо на ту же
ширину — и шапка, и навигация, и содержимое:

```css
@media (min-width: 992px) {
    .layout-wrapper.layout-has-rail .layout-topbar {
        left: var(--cross-service-rail-width);
        width: calc(100% - var(--cross-service-rail-width));
    }

    .layout-wrapper.layout-has-rail.layout-static:not(.layout-static-inactive)
        .layout-sidebar {
        left: calc(2rem + var(--cross-service-rail-width));
    }

    .layout-wrapper.layout-has-rail.layout-static .layout-main-container {
        margin-left: calc(22rem + var(--cross-service-rail-width));
    }
}
```

Ширину берите **переменной**, а не числом: два числа разойдутся.

Три подсказки из опыта встраивания в оболочку Sakai:

- **Шапка начинается правее рейла, а не над ним.** Рейл — самый внешний слой,
  и гамбургер, сворачивающий навигацию продукта, обязан лежать внутри шапки,
  а не над чужой полосой.
- **Сдвигать навигацию нужно только пока она развёрнута.** Свёрнутую оболочка
  уводит за левый край, и заданный `left` вернул бы её краем в кадр поверх
  рейла.
- **Содержимое сдвигается вместе с навигацией.** Иначе она наезжает на него
  и срезает левый край заголовков.

Класс `layout-has-rail` ставится по непустому составу пунктов: при пустом
перечне рейла нет, и место резервировать не нужно.

## Переменные оформления

**Цвета трёх видов навигации — палитра пакета, а не переменные темы продукта.**
Рейл — навигация **установки**, а не раздел продукта: одни и те же сервисы,
один и тот же порядок, одно и то же место на экране во всех продуктах. Следуя
чужой палитре, он выглядел бы в каждом по-своему, и узнавание — единственное,
ради чего он существует, — терялось бы. Поэтому привести полосу к своей
палитре продукт не может.

**Вариантов у палитры два — светлый и тёмный**, и продукт выбирает между ними
своим признаком темы (см. [Тёмная тема](#тёмная-тема)). Выбирает он вариант,
а не цвета. До 0.4.8 вариант был один, и в тёмной теме продукта полоса
оставалась светлой.

Искать в полосе `--surface-*` или `--highlight-*` не нужно: их там нет. Фон,
наведение, нажатие, подсветка текущего пункта и подсказка берутся из токенов
пакета `--cross-service-color-*` со значениями макета.

Переменные темы читает **блок пользователя**: `UserMenu` стоит в шапке
продукта, среди его собственных элементов, и выпадать из неё не должен.
Из палитры пакета он берёт одно — подсветку раскрытого триггера и цвет его
стрелки (макет, кадры 4b и 5d): так видно, чьё меню раскрыто.

| Переменная | Запасное | Где видна |
| --- | --- | --- |
| `--text-color` | `#1f2937` | имя пользователя, пункты меню |
| `--text-color-secondary` | `#6b7280` | адрес почты, стрелка, значки пунктов |
| `--surface-hover` | `#f4f6f8` | триггер и пункт меню под курсором |
| `--surface-overlay` | `#fff` | фон выпадающего меню |
| `--surface-border` | `#e5e7eb` | граница меню, разделитель под шапкой |
| `--content-border-radius` | `6px` | скругление меню |
| `--primary-color`, `--primary-contrast-color` | `#10b981`, `#fff` | аватар |

Ещё две читают все компоненты сразу:

| Переменная | Запасное | Где видна |
| --- | --- | --- |
| `--transition-duration` | `0.2s` | переход фона пункта, поворот стрелки |
| `--focus-ring-width/style/color` | `1px`, `solid`, `currentcolor` | обводка фокуса |

Запасное значение есть у каждой — на «голой» странице файл не рассыпается. Оно
и остаётся **запасным**: зашитое вместо переменной, оно перестало бы следовать
теме продукта.

Своих переменных пакет объявляет три:

| Переменная | Значение | Зачем |
| --- | --- | --- |
| `--cross-service-rail-width` | `64px` | ширина полосы; её же читает сдвиг оболочки продукта |
| `--cross-service-rail-padding` | `12px` | отступ полосы сверху и снизу; его гасит плитка логотипа |
| `--cross-service-bar-z-index` | `1000` | слой закреплённой плашки внизу экрана |

Переопределять первые две незачем: ширину продукт не повторяет числом, а берёт
переменной — пока так, разойтись эти два значения не могут. Третью
переопределяют, когда слои оболочки устроены иначе (см. [Слой](#слой)).

Четвёртая переменная, `--cross-service-bar-height`, **не объявлена**: её ставит
на корне документа сама плашка, измеряя свой отрисованный узел. Объявленного
умолчания у неё нет намеренно — оно пришлось бы гасить на широком экране,
а порога, на котором плашка сменяет полосу, пакет не знает. Читайте её
с запасным нулём: `var(--cross-service-bar-height, 0px)`.

Кроме них пакет объявляет **токены палитры** `--cross-service-color-*`
и фирменные `--cross-service-brand`, `--cross-service-brand-contrast`. Это
не контракт с продуктом: переопределять их нельзя. Технически переопределение
сработает, но полоса перестанет выглядеть так же, как в остальных продуктах
установки, — ровно то, от чего палитра пакета защищает.

## Тёмная тема

**Продукту на Vue делать ничего не нужно, если его переключатель темы ставит
класс `.app-dark`.** Так устроена оболочка Sakai (`darkModeSelector:
'.app-dark'`), на которой собраны продукты установки: класс на `<html>`
включает тёмную палитру навигации в тот же момент, что и тёмную тему
продукта, без перезагрузки.

Класс работает на любом предке навигации, но надёжнее всего — на `<html>`:
подсказка полосы выносится в `body` и берёт цвета оттуда.

Другой признак темы у продукта (атрибут, класс с иным именем) пакет
не угадывает. Такой продукт ставит `.app-dark` на `<html>` рядом со своим
признаком. Системную тему (`prefers-color-scheme`) пакет не читает: тему
выбирает продукт, и собственное решение пакета разошлось бы с его
переключателем.

Продукт не на Vue включает тему атрибутом элемента — см.
[Пользовательский элемент](web-component.md#тема).

Значения — из макета, раздел «5 · тёмная тема»:

| Роль | Светлая | Тёмная |
| --- | --- | --- |
| Фон полосы и плашки | `#f4f4f4` | `#1c1c1f` |
| Граница | `#e6e6e6` | `#2a2a2e` |
| Пункт в покое | `#5c5c5c` | `#a1a1a8` |
| Наведение | `#e8e8e8` | `#2a2a2e` |
| Нажатие | `#e4e4e4` | `#2a2a2e` |
| Заливка текущего пункта | `#e9e4fb` | `#2d2748` |
| Акцент: текущий пункт, заголовок блока, риска | `#8265ea` | `#b3a4f7` |
| Заглушка первой буквой: фон / буква | `#eef2f6` / `#6b7280` | `#2a2a2e` / `#a1a1a8` |
| Шов блока в меню | `#eef2f6` | `#2a2a2e` |
| Подсказка: фон / текст | `#1b1b1b` / `#fff` | `#f2f2f2` / `#1b1b1b` |
| Всплывающий список: фон / граница / шов | `#fff` / `#e6e6e6` / `#ececec` | `#232327` / `#34343a` / `#34343a` |
| Затемнение под списком | 28 % | 50 % |
| Логотип, заливка заглушки текущего пункта | `#8265ea` | `#8265ea` |

Акцент в тёмной теме осветлён: исходный `#8265ea` на тёмном фоне не добирает
контраста. Логотип и заливка заглушки остаются в исходном — под ними белое.

## Иконки

**Шрифта иконок пакет не требует и не использует.** Иконки пунктов рейла —
файлы SVG, приходящие подписанными ссылками (`NavItem.iconUrl`); значки блока
пользователя и шестерёнка настроек нарисованы в самих компонентах. Подключать
`primeicons` ради компонентов не нужно.

Иконка — 22 px; файл вписывается целиком (`mask-size: contain`). Плашки под
иконкой больше нет: активность пункта выражена **заливкой самой кнопки**,
и второй фон под иконкой спорил бы с ней тоном. Продукт вправе изменить размер
переопределением `.cross-service-nav .cross-service-nav__icon`.

**Файл рисуется маской, а не изображением, и потому следует цвету состояния.**
Из файла берётся силуэт, а заливка — из `currentColor` ссылки: у текущего
пункта иконка окрашивается акцентом вместе с подписью. Изображением она цвету
не следовала — внешний файл цвет страницы не наследует, и `currentColor` внутри
него разрешался в чёрный: пункты выходили чёрными вместо серых, а текущий
не окрашивался вовсе. Наведение цвет не меняет — у него один только фон,
и иконка под курсором остаётся прежней.

Цена — **одноцветность**: маска берёт силуэт, и многоцветный знак обратится
в одну заливку. Отсюда обязанность **администратора установки**, а не продукта:
заводить линейные значки одного тона. Продукту здесь делать нечего — файл
он не выбирает.

**Хранилище иконок установки обязано отдавать `Access-Control-Allow-Origin`.**
Маску браузер загружает запросом CORS, и без разрешения она не применяется.
Это настройка установки, у продукта средств нет; признак — заглушки первой
буквой вместо иконок у всех пунктов сразу.

**Сбой загрузки иконки повторяется, а не сдаётся сразу** (с 0.4.7). После
ошибки файл загружается ещё дважды — через 0.5 и 2 с, — и первая буква
появляется лишь после третьей неудачи: кратковременный сбой хранилища (обрыв
соединения, 5xx) больше не заменяет иконку буквой до перезагрузки страницы.
Маска ставится только после удачной загрузки файла — до неё пункт прозрачен,
а не залит цветом, и сбой одной маски не оставляет пункт пустым.

Заглушка первой буквой — собственный узел компонента: у неё есть фон
и скругление, а у текущего пункта она акцентная. Размер буквы задан
пикселями (9.625 px), а не `rem`: от корня документа он не зависит.

**Разделитель справа от полосы нарисован внутренней тенью, а не границей**
(с 0.4.7). Плитка логотипа поэтому идёт во всю ширину полосы и закрывает
его: прежде справа от логотипа оставалась светлая полоса в пиксель, заметная
на тёмной теме продукта. Ширина полосы и положение пунктов не изменились.

Значок шестерёнки цвет **наследует напрямую**: он встроенный SVG, а не файл
из хранилища, и маской не красится — фон под ним снят отдельным правилом.

Селектор плашки остался двухклассовым, хотя набора иконок у рейла больше нет:
продукт вправе подключать PrimeIcons ради собственной навигации, и `.pi {
display: inline-block }` снова оказалось бы той же силы каскада, что
одноклассовый селектор плашки, — исход решал бы порядок загрузки файлов.

## Чего не делать

- Не править файл стилей копией в продукте: правка идёт в пакет
  ([Правка эталона](contributing.md)).
- Не заводить пороги ширины внутри компонентов или их стилей.
- Не опираться на классы оболочки продукта в правилах рейла: он не должен
  зависеть от состояния чужой навигации.
