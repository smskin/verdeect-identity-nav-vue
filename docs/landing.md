# Лендинг без бэкенда

Страница режима **«Лендинг без бэкенда»**. Если у вашего приложения есть
серверная часть и вход через identity, это не ваш режим — читайте
[Установку и подключение](installation.md) и [Состояние рейла](state.md).

## Когда этот режим

Лендинг — статический SPA на Vue: серверной части нет, пользователь не входит.
Секрета клиента держать негде, и служебного токена лендинг не получит. Состав
рейла он берёт **публичной операцией** установки прямо из браузера.

Компоненты те же, что у продукта установки: `CrossServiceRail`,
`CrossServiceMenu`, `CrossServiceBar`. Данные для них даёт вход
`@verdeect/identity-nav-vue/public`.

**Что в этом режиме недоступно:**

- `UserMenu` — никто не вошёл, и показывать нечего;
- шестерёнка настроек — у гостя нет профиля;
- пункты для вошедших и администраторов — лендинг видит только гостевой
  состав.

## Что нужно на стороне identity

1. **Установка с публичной операцией** `GET /api/public/navigation`
   (PRD навигации 5.8).
2. **Операция включена развёртыванием**:
   `IDENTITY_NAVIGATION_PUBLIC_ENABLED=true`. По умолчанию она выключена
   и отвечает `404`.
3. **Пункты, которые должны быть видны, отмечены аудиторией «гость»**
   на экране «Навигация» установки.

При включённой операции гостевой пункт виден **любому в интернете** — это
решение администратора установки, а не лендинга.

## Установка и стили

```bash
npm install @verdeect/identity-nav-vue
```

```css
@import '@verdeect/identity-nav-vue/style.css';
```

Требования те же, что у продукта: Vue 3.5+ и Vite с `@vitejs/plugin-vue` —
пакет поставляется исходниками ([Установка](installation.md)).

## Получение данных

```vue
<script setup lang="ts">
import { useRoute } from 'vue-router';
import { CrossServiceBar, CrossServiceRail } from '@verdeect/identity-nav-vue';
import { usePublicNavigation } from '@verdeect/identity-nav-vue/public';

const route = useRoute();

const { crossService, locale, hasRail, currentUrl, failure } = usePublicNavigation({
    baseUrl: 'https://id.example.com',
    locale: () => 'ru',
    path: () => route.fullPath,
});
</script>
```

Композиция вызывается в `setup`. Запрос уходит при монтировании компонента
и прерывается при размонтировании.

| Опция | Тип | Значение |
| --- | --- | --- |
| `baseUrl` | `string` | адрес установки identity; берётся только origin |
| `locale` | `() => string` | язык подписей |
| `path` | `() => string`, необязательна | путь открытой страницы |

**`path` передавайте, если у лендинга есть маршрутизатор.** Без опции путь
читается из окна, но чтение окна не реактивно: переход внутри SPA подсветку
не обновит.

| Значение | Содержимое |
| --- | --- |
| `crossService` | `items`, `logoUrl`, `profileUrl` (всегда пустой) |
| `locale` | язык подписей |
| `hasRail` | состав пунктов непуст |
| `currentUrl` | абсолютный адрес открытой страницы |
| `loading` | истина, пока ответ не получен |
| `failure` | причина отсутствия рейла либо `null` |

Поля ответа (`icon_url`, `logo_url`) композиция уже переложила в форму
компонентов — `iconUrl`, `logoUrl`. Кэша в пакете нет: ответ кэширует
установка, а браузер держит его по `Cache-Control`.

## Монтирование

Полоса и **один** мобильный вид — какой, решаете вы:

```vue
<template>
    <CrossServiceRail
        v-if="hasRail"
        :items="crossService.items"
        :locale="locale"
        :logo-url="crossService.logoUrl"
        :current-url="currentUrl"
    />

    <CrossServiceBar
        v-if="hasRail"
        :items="crossService.items"
        :locale="locale"
        :current-url="currentUrl"
    />

    <div class="page" :class="{ 'page--has-rail': hasRail }">
        <RouterView />
    </div>
</template>
```

- **`profileUrl` не передаётся** — шестерёнки у гостя нет.
- **`UserMenu` не монтируется.**
- **Условие показа — `hasRail`**: пустой состав либо отказ загрузки дают страницу
  без рейла.
- **Мобильные виды взаимоисключающие.** `CrossServiceBar` — плашка внизу,
  `CrossServiceMenu` — блок в выдвижном меню, если оно у лендинга есть. Доводы
  «за» и «против» — в [Встраивании](embedding.md).

## Порог и сдвиг вёрстки

Порог переключения видов принадлежит лендингу: в пакете его нет. Правила
переключения — как в [Оформлении](styling.md), по `data-placement`:

```css
@media (min-width: 992px) {
    [data-placement='bottom'] {
        display: none;
    }

    .page--has-rail {
        margin-left: var(--cross-service-rail-width);
    }
}

@media (max-width: 991px) {
    [data-placement='rail'] {
        display: none;
    }

    /* Только если выбрана CrossServiceBar. */
    [data-placement='bottom'] {
        position: fixed;
        left: 0;
        right: 0;
        bottom: 0;
        z-index: 1000;
    }

    .page--has-rail {
        padding-bottom: calc(49px + env(safe-area-inset-bottom, 0px));
    }
}
```

Полоса лежит `position: fixed` слева, поэтому содержимое страницы сдвигается
на её ширину. Ширину берите **переменной**, а не числом. Правила держите
**вне `@layer`**.

**Плашку к низу экрана прижимаете вы.** `CrossServiceBar` объявлена
`position: relative` и без правила выше встанет первой строкой страницы.
Отступ снизу — её высота, 49 px плюс безопасная зона: без него конец страницы
уйдёт под плашку. Подробности — в [Оформлении](styling.md#закрепление-плашки).
Выбрав `CrossServiceMenu`, оба правила не пишите.

## Отказы

Посетитель в любом случае видит страницу — просто без рейла. Причину читайте
в `failure`:

| `failure` | Что произошло | Что делать |
| --- | --- | --- |
| `disabled` | публичная операция выключена (`404`) | включить `IDENTITY_NAVIGATION_PUBLIC_ENABLED` в установке |
| `rate_limited` | превышена частота с адреса посетителя (`429`) | ничего: рейл появится при следующей загрузке страницы |
| `unavailable` | сеть недоступна либо установка ответила ошибкой | проверить адрес и доступность установки, `connect-src` |
| `malformed` | ответ не по контракту | проверить, что `baseUrl` ведёт на установку identity |
| `misconfigured` | непригодный `baseUrl`; запроса не было | указать origin со схемой `https` |

Повтора по таймеру пакет не делает намеренно: при `429` он нагрузил бы
установку ровно тогда, когда она просит сбавить частоту.

## Политика содержимого

| Директива | Origin | Зачем |
| --- | --- | --- |
| `connect-src` | установки identity | запрос состава рейла |
| `img-src` | установки identity | логотип |
| `img-src` | хранилища иконок | иконки пунктов; origin виден в ссылках `iconUrl` |

Хранилище иконок установки обязано отдавать `Access-Control-Allow-Origin`:
иконка рисуется маской, а маску браузер загружает запросом CORS. Настраивается
это на стороне установки; признак — первые буквы имён вместо иконок у всех
пунктов.

## Кэш

Ответ кэшируется установкой и браузером на срок из её настроек (по умолчанию
минута). Изменение реестра доходит до лендинга не мгновенно — это штатно.

**Не добавляйте к адресу меток против кэша.** Параметров у операции нет,
и любой даёт `400`: композиция их не добавляет, а собственный запрос в обход
неё делать незачем.

## Чек-лист лендинга

- [ ] В установке включена публичная операция, нужные пункты отмечены «гостем»
- [ ] Стили пакета подключены
- [ ] `usePublicNavigation` вызвана в `setup` с origin установки
- [ ] `path` передан из маршрутизатора, если он есть
- [ ] Смонтированы полоса и **один** мобильный вид, оба под `v-if="hasRail"`
- [ ] `profileUrl` не передан, `UserMenu` не смонтирован
- [ ] Правила переключения — со своим порогом и **вне `@layer`**
- [ ] Содержимое сдвинуто на `--cross-service-rail-width`, пока рейл есть
- [ ] Если выбрана `CrossServiceBar`: плашка закреплена у нижнего края,
      содержимому дан отступ снизу на её высоту
- [ ] `connect-src` и `img-src` включают origin установки, `img-src` — origin
      хранилища иконок
