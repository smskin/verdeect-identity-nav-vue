# Установка и подключение

Страница для **всех режимов** подключения.

Пакет поставляется **исходниками** — `.vue`, `.ts` и `.css` без шага сборки.
Собирает их интерфейс потребителя. Единственное исключение — вход `./element`
для продуктов не на Vue: это готовый файл, собранный при упаковке пакета.

## Два режима

| | Продукт установки | Лендинг без бэкенда |
| --- | --- | --- |
| Кто | Приложение с серверной частью и входом через identity | Статический SPA без серверной части и без входа |
| Откуда данные | Бэкенд продукта (`verdeect/identity-laravel`) | Браузер напрямую из identity |
| Вход пакета | `./inertia` либо `./identity` | `./public` |
| Что показывается | Навигация по роли, шестерёнка настроек, `UserMenu` | Только гостевая навигация |
| Условие на стороне identity | Служебный клиент с областью `navigation:read` | Включена публичная операция `GET /api/public/navigation` |

Компоненты в обоих режимах одни и те же. Лендингу посвящена отдельная страница —
[Лендинг без бэкенда](landing.md).

**Продукт не на Vue** (Svelte, React, страница без сборщика) данные получает
так же, как продукт установки: их готовит его бэкенд. Компоненты он берёт
готовым пользовательским элементом из входа `./element`. Требования ниже
к нему не относятся: Vue лежит внутри файла, а Vite продукту не нужен.
Подробно — [Пользовательский элемент](web-component.md).

## Требования

| Что | Зачем |
| --- | --- |
| Vue 3.5+ | компоненты написаны на `<script setup lang="ts">` |
| Vite с `@vitejs/plugin-vue` | плагин обрабатывает `.vue` в зависимостях наравне со своими |

**Шрифта иконок пакет не требует.** Иконки пунктов рейла приходят подписанными
ссылками на файлы SVG, значки блока пользователя встроены в компонент. Это
и было поводом отказаться от набора: шрифт пришлось бы подключать в каждом
продукте установки, а продукты о нём не знают и подключать не обязаны.

Собранного бандла у входов из исходников нет намеренно: продукт на Vue
собирает их своим Vite. Собирается только `./element`, потому что продукту
не на Vue собрать `.vue` нечем. Сборка идёт на `prepack`, а не на `prepare`:
установка из git её не тянет, и поэтому `./element` есть только у пакета
из реестра npm.

## Установка

```bash
npm install @verdeect/identity-nav-vue
```

Пакет опубликован в публичном реестре npm, поэтому ни ключа, ни токена для
установки не нужно — ни на машине разработчика, ни в контейнере сборки, ни на
конвейере. Исходники лежат на [GitHub](https://github.com/smskin/verdeect-identity-nav-vue)
под лицензией MIT.

Одноранговые зависимости, кроме `vue`, объявлены необязательными — ставится
только то, что продукт действительно потребляет.

| Зависимость | Обязательна | Когда нужна |
| --- | --- | --- |
| `vue` | да | для всех входов, кроме `./element` (Vue внутри файла) |
| `@inertiajs/vue3` | нет | только для входа `./inertia` |
| `@playwright/test` | нет | только для входа `./playwright` |

## Семь входов

```ts
import { CrossServiceRail, CrossServiceMenu, UserMenu } from '@verdeect/identity-nav-vue';
import { useIdentity } from '@verdeect/identity-nav-vue/inertia';
import { useIdentityView } from '@verdeect/identity-nav-vue/identity';
import { usePublicNavigation } from '@verdeect/identity-nav-vue/public';
import { loginAs } from '@verdeect/identity-nav-vue/playwright';
```

```css
@import '@verdeect/identity-nav-vue/style.css';
```

| Вход | Содержимое | Зависимости |
| --- | --- | --- |
| `.` | `CrossServiceRail`, `CrossServiceMenu`, `CrossServiceBar`, `UserMenu` и их типы | `vue` |
| `./style.css` | визуальный слой | — |
| `./identity` | вывод состояния рейла и профиля, типы | `vue` |
| `./inertia` | адаптер над `usePage()` | `vue`, `@inertiajs/vue3` |
| `./public` | `usePublicNavigation`: гостевой состав из браузера, типы | `vue` |
| `./playwright` | `loginAs`, `logout`, `credentialsFor` | `@playwright/test` |
| `./element` | пользовательский элемент `verdeect-identity-nav`, собранный файл `dist/element.js` | — (Vue внутри) |

**Продукт на Inertia** берёт `.`, `./style.css` и `./inertia`.
**Продукт на другом стеке** — те же, но вместо адаптера `./identity`,
и `@inertiajs/vue3` не ставит вовсе.
**Сама установка** обходится входами `.` и `./style.css`: данные рейла она
порождает, а не получает.
**Лендинг без бэкенда** — `.`, `./style.css` и `./public`; ни
`@inertiajs/vue3`, ни `@playwright/test` не ставит.
**Продукт не на Vue** — один `./element`: копирует `dist/element.js` в свою
статику либо импортирует `@verdeect/identity-nav-vue/element` своим сборщиком.

## Проверка подключения

```bash
npm ls @verdeect/identity-nav-vue   # разрешился ли пакет
npm run build                               # .vue из зависимости собирается
```

Если сборка спотыкается о `.vue` внутри `node_modules`, проверьте, что
`@vitejs/plugin-vue` подключён в `vite.config.ts` и что предварительная сборка
зависимостей не пытается обрабатывать пакет как готовый бандл — в этом случае
исключите его через `optimizeDeps.exclude`, а не отключением проверок.
