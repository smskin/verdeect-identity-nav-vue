# Правка эталона

Компоненты рейла и блока пользователя существуют в экосистеме **в одном
экземпляре** — в этом пакете. Продукты получают правку обновлением
зависимости.

## Почему копировать нельзя

Однажды уже разошлись. К моменту выделения библиотеки файлы жили в трёх местах:
в установке, во встроенном composer-пакете продукта и в самом продукте.
Компоненты совпадали, но их документация и стили разъехались попарно,
и сведение обошлось в отдельную работу по сверке каждого расхождения.

Правка «только у себя, потом перенесу» — тот же путь. Переносят не всегда.

## Правила каталога `src/cross-service`

Каталог обязан оставаться переносимым: внутри допустимы `vue`, собственные
файлы и классы `pi pi-*`. Проверяется `npm run check:isolation`:

| Запрет | Причина |
| --- | --- |
| сетевые обращения (`fetch`, `XMLHttpRequest`, `WebSocket`…) | данные приходят только props |
| браузерные хранилища, `document.cookie` | кэш живёт на бэкенде продукта |
| импорты, кроме `vue` и локальных файлов | иначе каталог перестанет быть переносимым |
| адреса вида `http(s)://` | адреса приходят в данных |
| слово `token` | ключей доступа в браузере не бывает |
| числовые пороги ширины, `matchMedia`, `innerWidth` | порог принадлежит продукту |
| обращения к `document` вне двух разрешённых файлов | перечень закреплён константой с доводом |
| обращения к консоли, кроме одного в `strings.ts` | и то обёрнуто проверкой режима разработки |

Девятым условием тот же скрипт проверяет, что ядро `src/identity` разбирается
**без** `@inertiajs/vue3`: знание про Inertia живёт только в адаптере.

Перечень разрешённых обращений к `document` правится вместе с доводом здесь же —
иначе он перестанет что-либо значить.

## Словарь подписей

Строки компонентов лежат в `src/cross-service/strings.ts`, а не в файлах
переводов продукта: продукт, встроивший рейл, словаря установки не ведёт.

Языки — `ru` и `en`: столько же, сколько у экранов входа установки, и `locale`
из `/userinfo` принимает одно из них. Неизвестный язык компонент отдаёт
запасным.

`npm run check:strings` проверяет: состав ключей совпадает между языками, оба
языка объявлены, все ключи, вызываемые компонентами, существуют. Формат словаря
обязан оставаться **плоским** — вложенность роняет разбор явной ошибкой.

## Прогон перед правкой и после

```bash
npm test
```

Словарь, изоляция, типы, правило подсветки. Прогон быстрый — гоняйте его
на каждое изменение каталога.

## Совместимость с бэкендом

Состав `NavItem` совпадает с ответом операции `POST /api/users/services`
установки, а формы имени — с тем, что считает composer-пакет
`verdeect/identity-integration`. Границу держат две пары:

| В PHP | В TypeScript |
| --- | --- |
| `NavigationData.items` | `NavItem[]` |
| `UserProfile` | `IdentityProfile` |

Библиотеки лежат в разных репозиториях, и расхождение здесь пройдёт **молча**:
ни один прогон его не увидит. Поэтому изменение состава полей — согласованное
изменение обеих библиотек с согласованным minor, а не правка одной из них.

## Версии

Тег `vX.Y.Z` в репозитории; продукты подключаются по тегу. Правило —
одинаковый minor у обеих библиотек интеграции.

## Что менять нельзя без веской причины

- **Состав экспортов входа `.`** — продукты импортируют оттуда компоненты
  и типы.
- **Обязательность `placement`** — умолчание вернуло бы два видимых
  представления сразу.
- **Имена `data-testid`** — на них опираются браузерные сценарии продуктов.
- **Имя переменной `--cross-service-rail-width`** — по ней продукты сдвигают
  оболочку.
